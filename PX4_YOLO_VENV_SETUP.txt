IMPORTANT DESIGN
----------------
Do not reinstall ROS 2 with pip inside the virtual environment.
ROS 2 packages such as rclpy, cv_bridge, sensor_msgs and launch must come from
/opt/ros/humble. The virtual environment is only for YOLO, PyTorch, OpenCV and
other project-specific Python libraries.

The attached bringup_px4_yolo.launch.py uses this default executable:

    /home/tnourji/px4-venv/bin/python

Therefore, use the exact directory name "px4-venv" with a hyphen, not
"px4_venv" with an underscore.


1. Install system prerequisites
-------------------------------
Open a clean terminal and run:

    sudo apt update
    sudo apt install -y python3-venv python3-pip python3-dev \
        ros-humble-cv-bridge ros-humble-rclpy \
        ros-humble-sensor-msgs ros-humble-image-transport

Do not run sudo pip install.


2. Remove only an incorrect or incomplete old environment
----------------------------------------------------------
This removes only the Python virtual environment. It does not remove ROS 2,
PX4, Gazebo, source code, or the ROS workspace.

    deactivate 2>/dev/null || true
    rm -rf /home/tnourji/px4-venv


3. Create the virtual environment using Ubuntu system Python
------------------------------------------------------------
The --system-site-packages option is important because the YOLO node must be
able to import ROS 2 Python packages installed under /opt/ros/humble.

    /usr/bin/python3 -m venv --system-site-packages /home/tnourji/px4-venv
    source /home/tnourji/px4-venv/bin/activate

Confirm that the correct interpreter is active:

    which python
    python --version

Expected:

    /home/tnourji/px4-venv/bin/python
    Python 3.10.x

Upgrade Python packaging tools inside the environment:

    python -m pip install --upgrade pip setuptools wheel

--------------------------

8. Run the launch file
----------------------
Every time a new terminal is opened, use this order:

    source /home/tnourji/px4-venv/bin/activate
    source /opt/ros/humble/setup.bash
    export RMW_IMPLEMENTATION=rmw_fastrtps_cpp

Then launch:

The attached launch file already defaults to:

    yolo_venv_python:=/home/tnourji/px4-venv/bin/python
    camera_topic:=/camera
    model_path:=yolov8m.pt
    yolo_device:=0
    yolo_half:=true
    yolo_imgsz:=960

To explicitly pass the interpreter path:

    ros2 launch uav_camera_det_pkg bringup_px4_yolo.launch.py \
        yolo_venv_python:=/home/tnourji/px4-venv/bin/python

Example with explicit camera topic and model:

    ros2 launch uav_camera_det_pkg bringup_px4_yolo.launch.py \
        yolo_venv_python:=/home/tnourji/px4-venv/bin/python \
        camera_topic:=/camera \

Check the actual ROS camera topic before launching:

    ros2 topic list | grep -Ei "camera|image"

If the actual image topic is different, replace /camera. For example:

    ros2 launch uav_camera_det_pkg bringup_px4_yolo.launch.py \
        camera_topic:=/camera/image_raw

10. The old command you likely used
-----------------------------------
To export the packages from a working virtual environment:

    source /home/tnourji/px4-venv/bin/activate
    python -m pip freeze > requirements-px4-yolo.txt

To recreate that environment on another PC:

    /usr/bin/python3 -m venv --system-site-packages /home/tnourji/px4-venv
    source /home/tnourji/px4-venv/bin/activate
    python -m pip install --upgrade pip setuptools wheel
    python -m pip install -r requirements-px4-yolo.txt

However, a raw pip freeze from a ROS workstation may include machine-specific
editable entries such as:

    -e /home/old-user/.../build/uav_camera_det_pkg

Remove all such "-e /old/path/..." lines before using the file on another PC.
ROS packages installed through apt should remain system-managed rather than
being duplicated into the virtual environment with pip.
